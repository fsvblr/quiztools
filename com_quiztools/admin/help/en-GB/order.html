QuizTools: Creating and editing an order

This page is used to create a new order or edit an existing one.

General tab

Basic order settings are configured here.

Subscription

Required when an administrator creates a new order manually. Select the subscription that should become available to the user after the order status is changed to Confirmed.

This field is available only for orders created with the Manual payment method. After the first saving of the order, this field becomes read-only.

User

Required when an administrator creates a new order manually. Select the user to whom this order will be assigned. This user will be able to take the quiz or learning path linked to the selected subscription.

This field is available only for orders created with the Manual payment method. After the first saving of the order, this field becomes read-only.

Order status
Select the current order status. An order is available to a user on the front-end only when its status is Confirmed.
To allow users to access their own orders on the front-end, we recommend creating a menu item of the type "Orders List (My subscriptions)." The minimum access level for this menu item should be set to "Registered."
Payment method

For manually created orders, the payment method is always Manual. This option means that the order is created in the administrator area and payment is tracked manually.

For orders created automatically via a third-party e-shop component, the payment method is set automatically to the name of that e-shop component and cannot be changed.

Access start
Read-only field. It is generated from the subscription linked to the order after the order is first saved. It defines the date and time from which access to the subscription is available.
Access end
Read-only field. It is generated from the subscription linked to the order after the order is first saved. It defines the date and time until which access to the subscription is available.
Attempts max
Read-only field. It is generated from the subscription linked to the order after the order is first saved. It defines the maximum number of attempts allowed for this order.
Attempts used
Read-only field. It is calculated automatically based on the attempts that the assigned user has already made for this order. This field cannot be changed manually.
Order ID in e-store
Read-only field. It is filled automatically for orders created via a third-party e-shop component. It contains the order identifier from that e-shop.
Product ID in e-store
Read-only field. It is filled automatically for orders created via a third-party e-shop component. It contains the product identifier from that e-shop.

Manual order creation in the administrator area

An administrator can create a new order only with the Manual payment method. In this case, the Subscription, User, and Order status fields must be filled in before saving. After saving a manually created order, the only editable field is Order status. All other order fields become read-only because their values are determined by the linked subscription and the user's attempts.

Automatic order creation via an e-shop component

Orders can be created automatically in the administrator area if a third-party e-shop component is installed (for example, HikaShop or VirtueMart) and the corresponding QuizTools payment plugin is enabled and configured.

When a user places an order in the e-shop on the front-end, the corresponding order is automatically displayed in the QuizTools administrator area. For such orders, the payment method, order ID in the e-shop, and product ID in the e-shop are filled in automatically from the e-shop data and cannot be edited.

The “Reactivate” toolbar button

Clicking Reactivate opens a pop-up window where the administrator can extend this order. The following options are available in the pop-up:

  • Access to — change the date until which the order remains available. If the field is left blank, the order will be available for “lifetime” access, i.e. unlimited days. If a date is selected, the order will be available until that date, provided that the available number of attempts has not yet been used or is unlimited (zero).
  • Attempts — specify a new number of attempts. A new countdown of attempts begins from the moment the order is reactivated. Set the value to 0 (zero) for unlimited attempts.

Publishing tab

The Publishing tab shows service information about the record:

  • ID — unique number of the order in the database;
  • Created — date and time when the order was created;
  • Created by — user who created the order;
  • Modified Date — date of the last change;
  • Modified by — user who last changed the order.

These fields are filled in automatically and usually do not require manual changes.

Saving changes

For manually created orders, fill in at least the required fields Subscription, User, and Order status before saving. After the initial save, only Order status remains editable.

For orders created automatically through an e-shop component, the data is populated from the e-shop.
